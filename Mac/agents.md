# 用户全局协作约定

## 直接任务默认执行

- 对目标、范围和预期结果明确，不存在理解障碍或歧义的任务，直接完成，不再要求用户二次确认。
- 对上述明确任务不采用审批式工作流，不以方案确认、执行确认或测试确认作为开始实施的前置条件。
- 只有在需求存在歧义、需要扩大业务范围、改变已确认的设计方向或产生新的外部影响时，才先向用户说明并等待确认。

## 严格对齐范围

- 不得根据模糊上下文自行扩展业务功能、改变产品方向或替用户作出设计决策。
- 如果实施过程中发现需要扩大业务范围、改变已确认的设计方向或产生新的外部影响，必须暂停并重新与用户对齐。

## 补齐直接关联事项

- 范围明确后，应自主补齐与目标直接相关的依赖、完整性处理、安全措施、异常处理和上线保障。
- 这些关联工作应以避免因需求遗漏导致生产故障、安全问题或不可用状态为准，不需要用户逐项列出。
- 完成时应明确说明自主补齐了哪些关联事项及其原因，但不得借此实现无关业务或扩大已经确认的产品范围。

## 默认交付节奏

- 任务完成以代码实现完整、逻辑正确为准；用户未明确要求测试时，不执行测试，以最快速度交付。
- 对界面改动可以进行必要的基础视觉检查；除非用户明确要求，不扩展为完整自动化测试、兼容性测试或额外验收流程。
- 默认不进行移动端网页适配；仅在用户明确提出移动端要求时处理。

## 部署前强制验证

- 任何会触发部署的提交、合并或推送，必须先执行项目定义的完整测试、类型检查和服务端测试；存在聚合命令时优先使用聚合命令。
- 对 `lingkun-web`，部署前至少执行 `npm run test:all`，并确认单元测试、`vue-tsc` 类型检查和 `go test ./...` 全部通过。
- 任一部署前检查失败时，不得继续部署或推送；必须先修复失败项，并重新执行完整验证直至通过。
